# Обзор архитектуры

## Назначение проекта

`MiSKZI-Ciphers` — учебный репозиторий с реализациями классических шифров, единым программным контрактом, проверочными вариантами из методичек и Streamlit-интерфейсом для ручной проверки. Проект не пытается быть криптографическим фреймворком общего назначения; его основная задача — дать предсказуемую среду для практических работ.

## Подсистемы

### `src/miskzi_ciphers/ciphers/`

Каждый шифр лежит в отдельном подпакете вида `src/miskzi_ciphers/ciphers/<cipher_id>/cipher.py`. Подпакет экспортирует `get_cipher()` или `CIPHER`, а сам объект обязан соответствовать протоколу `Cipher` из `common/types.py`.

### `src/miskzi_ciphers/common/`

Общие функции и типы:

- `types.py` — протокол `Cipher`, типы `CipherInfo`, `ParamSpec`, `Variant`.
- `registry.py` — autodiscovery подпакетов шифров и загрузка конкретной реализации.
- `paths.py` — поиск каталога `data/`, в том числе через переменные окружения.
- `keyparse.py` — общие валидаторы сырых ключей.
- `alphabet.py`, `math_utils.py`, `io_utils.py` — вспомогательные примитивы.

### `src/miskzi_ciphers/app/service.py`

Тонкий сервисный слой между UI и шифрами. Он:

- выдаёт список шифров и описания;
- вызывает `parse_key()`, `encrypt()`, `decrypt()`;
- читает и сохраняет `variants.json`;
- мигрирует legacy `free_text.txt` в `meta.free_text`;
- валидирует структуру данных для Data Manager.

### `src/miskzi_ciphers/ui/`

Streamlit UI состоит из одного приложения `ui/app.py` и словаря локализации `ui/i18n.py`. Внутри приложения две страницы:

- Playground — запуск шифра на произвольном тексте или варианте;
- Data Manager — редактирование `meta` и списка вариантов для выбранного шифра.

### `data/`

Каталог учебных данных. Для каждого `cipher_id` ожидается подпапка `data/<cipher_id>/` c файлом `variants.json`. У `book_cipher` дополнительно есть `key.txt`.

### `tests/`

Тесты покрывают:

- контракт шифров и работу registry;
- сервисный слой;
- схему `variants.json` и `meta`;
- локализацию UI;
- контрольные векторы для части практик.

## Поток данных

Базовый путь исполнения выглядит так:

`пользователь -> UI -> app.service -> registry/load_cipher -> cipher.parse_key -> cipher.encrypt/decrypt -> UI`

Отдельный путь для учебных данных:

`Data Manager / Playground -> app.service.load_variants/load_meta -> data/<cipher>/variants.json`

## Основные архитектурные принципы

1. Шифры независимы друг от друга и общаются с системой только через единый контракт.
2. Registry не знает ничего о конкретной криптологической логике; он работает только по имени подпакета и обязательным методам.
3. UI не должен импортировать модули шифров напрямую; для этого существует `app/service.py`.
4. Структура учебных данных едина для всех шифров, даже если конкретный шифр использует не все поля.
5. Ошибки в ключе и входных данных поднимаются как исключения из `parse_key()/encrypt()/decrypt()` и доходят до UI без специальной прослойки трансляции.

## Инварианты

Следующие вещи считаются опорными и не должны меняться без веской причины:

- подпакет шифра называется так же, как `cipher.name`;
- каждый шифр реализует `name`, `describe()`, `parse_key()`, `encrypt()`, `decrypt()`;
- `describe()` возвращает словарь, пригодный для машинного чтения UI;
- `parse_key()` возвращает канонический `dict`, пригодный для повторного использования в `encrypt()/decrypt()`;
- `service.validate_variants_obj()` задаёт минимальный контракт формата `variants.json`;
- `variants.json` хранит корень вида `{"meta": {...}, "items": [...]}`;
- UI читает и пишет данные только через сервисный слой;
- registry подхватывает только подпакеты с `cipher.py`, где есть `get_cipher()` или `CIPHER`.

## Допустимые зависимости

- `ciphers/*` могут использовать `common/*`.
- `app/service.py` может использовать `common/*` и registry.
- `ui/*` может использовать `app/service.py` и `ui/i18n.py`.
- `tests/*` могут проверять все перечисленные слои.

Нежелательные зависимости:

- прямой импорт UI в коде шифров;
- прямой импорт конкретных шифров из UI вместо `service`;
- логика чтения `data/` внутри самих шифров, если это не часть их собственного ключа или данных шифра.

## Что не стоит менять без причины

- сигнатуры методов шифра;
- схему `describe().params`;
- модель autodiscovery в `common/registry.py`;
- корневую структуру `variants.json`;
- ключи `session_state`, на которые завязан Streamlit UI;
- соглашение, что `service` делает только координацию, а не переписывает криптологику.
