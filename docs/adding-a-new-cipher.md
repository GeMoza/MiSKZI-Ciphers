# Как добавить новый шифр

## 1. Создать подпакет

Создайте каталог:

`src/miskzi_ciphers/ciphers/<cipher_id>/`

Минимальный состав:

- `__init__.py`
- `cipher.py`

`<cipher_id>` сразу выбирайте как стабильный системный идентификатор. Он будет использоваться в registry, `data/`, локализации и тестах.

## 2. Реализовать `cipher.py`

Внутри нужен объект шифра, который соответствует контракту из `common/types.py`, и экспорт:

- либо `get_cipher()`;
- либо `CIPHER`.

На практике в проекте чаще используется `get_cipher()`.

## 3. Реализовать контракт

Обязательные части:

- `name`
- `describe()`
- `parse_key()`
- `encrypt()`
- `decrypt()`

До написания логики полезно сначала собрать `describe()` и `parse_key()`: от них зависят UI и тесты интеграции.

## 4. Оформить `describe()`

Минимальная рекомендация:

- `name` должен совпадать с `cipher_id`;
- `title` — краткое отображаемое название;
- `family` — уже существующее семейство или аккуратно добавленное новое;
- `params` — реальный список параметров ключа;
- `notes` — краткое техническое описание ограничений, регистра и особенностей обработки текста.

Для каждого параметра укажите хотя бы:

- `name`
- `type`
- `required`

Желательно также добавить `help`, `default`, `choices`, `example`.

## 5. Организовать `parse_key()`

`parse_key()` должен:

- принимать сырой `dict`;
- отвергать неизвестные поля, если это уместно;
- требовать обязательные параметры;
- приводить типы;
- возвращать канонический словарь.

В проекте для этого уже есть helpers в `common/keyparse.py`: `require`, `optional`, `as_int`, `as_bool`, `as_str`, `as_enum_*`, `as_char`, `reject_unknown_keys`.

## 6. Добавить данные

Создайте каталог:

`data/<cipher_id>/`

И файл:

`data/<cipher_id>/variants.json`

Минимально полезно положить туда:

- `meta.free_text`
- `meta.notes`
- `meta.raw_key_example`
- хотя бы 1-2 варианта в `items`

`key` внутри варианта должен быть сырым ключом, который успешно проходит через `parse_key()`.

## 7. Проверить registry и UI

После добавления шифра проверьте:

1. шифр виден в `REGISTRY.list_names()`;
2. `REGISTRY.load("<cipher_id>")` не падает;
3. он появляется в списке UI;
4. форма ключа строится по `describe().params`;
5. загрузка `free_text` и `raw_key_example` работает;
6. Data Manager сохраняет варианты без ошибок валидации.

## 8. Добавить локализацию

Для хорошего UX обычно нужно обновить `ui/i18n.py`:

- `CIPHER_LABELS`
- `PARAM_LABELS`
- `PARAM_HELPS`
- `PARAM_VALUE_LABELS`, если есть enum

Без этого UI будет показывать сырой `cipher_id` и технические имена параметров.

## 9. Добавить минимальные тесты

Минимум для нового шифра:

1. хотя бы один тест на `parse_key()`
2. хотя бы один roundtrip-тест
3. если есть методичка или контрольный пример — тест на ожидаемый вектор
4. проверка `variants.json` через общий `pytest -q`

Если шифр использует особые ограничения по алфавиту, регистру или блочности, добавьте отдельный тест именно на эту границу.
