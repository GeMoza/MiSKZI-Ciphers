# Registry и загрузка шифров

## Где находится логика

Загрузка шифров централизована в `src/miskzi_ciphers/common/registry.py`.

Основные сущности:

- `CipherRef` — ссылка на шифр: `name + module`.
- `CipherRegistry` — словарь зарегистрированных шифров и методы `list_names()/has()/load()`.
- `discover_cipher_modules()` — autodiscovery подпакетов.
- глобальный `REGISTRY` — готовый реестр, собранный при импорте модуля.

## Как работает autodiscovery

`discover_cipher_modules()` делает следующее:

1. перечисляет подпакеты под `miskzi_ciphers.ciphers`;
2. для каждого подпакета пытается импортировать модуль `miskzi_ciphers.ciphers.<name>.cipher`;
3. если импорт успешен и модуль экспортирует `get_cipher()` или `CIPHER`, модуль считается валидным кандидатом;
4. итоговый список модулей превращается в `CipherRef`, где `name` берётся из имени подпакета.

Если импорт модуля падает, модуль просто пропускается, а в debug-лог пишется причина.

## Как шифр становится доступен системе

Чтобы новый шифр автоматически появился в проекте, нужны все условия сразу:

1. есть подпакет `src/miskzi_ciphers/ciphers/<cipher_id>/`;
2. внутри есть `cipher.py`;
3. модуль импортируется без исключения;
4. он экспортирует `get_cipher()` или `CIPHER`;
5. объект шифра проходит `_validate_cipher()`;
6. его `name` совпадает с `<cipher_id>`.

После этого шифр автоматически появится в:

- `REGISTRY.list_names()`;
- `app.service.list_ciphers()`;
- списке шифров в UI;
- параметризованных тестах, которые итерируются по registry.

## Требования к имени подпакета и `cipher.name`

В проекте есть жёсткая связка:

- имя подпакета `src/miskzi_ciphers/ciphers/<cipher_id>/`
- значение `cipher.name`
- имя каталога `data/<cipher_id>/`

Если хотя бы одна часть не совпадает, появятся проблемы:

- registry отклонит шифр при загрузке;
- UI не сможет найти данные;
- локализация по `cipher_id` перестанет работать;
- тесты контрактов и данных будут путаться.

## Что именно валидирует registry

При `load()` реестр проверяет:

- наличие `name`;
- наличие и вызываемость `encrypt`, `decrypt`, `describe`, `parse_key`;
- непустую строку в `name`;
- совпадение `name` с ожидаемым именем из `CipherRef`;
- что `describe()` возвращает `dict`.

Registry не проверяет корректность криптографической логики. Этим занимаются тесты и ручная проверка.

## Типичные причины, почему шифр не подхватывается

- подпакет есть, но файл называется не `cipher.py`;
- модуль падает на импорте;
- нет `get_cipher()` и нет `CIPHER`;
- `cipher.name` не совпадает с именем подпакета;
- `describe()` возвращает не словарь;
- объект не реализует обязательные методы;
- подпакет не находится под `miskzi_ciphers.ciphers`.

## Что не стоит менять без причины

- схему autodiscovery через `pkgutil.iter_modules()`;
- правило, что `name` выводится из имени подпакета;
- контракт `get_cipher()` / `CIPHER`;
- наличие глобального `REGISTRY`, на который завязаны сервис и тесты.
