## Фиксация дефектов

### UI-PZ4-PZ5-001

**Шифр:** `richelieu`
**Область:** Variants / data quality
**Серьёзность:** medium
**Статус:** fixed

**Симптомы:** часть вариантов не выполняется из-за несоответствия длины текста и суммы размеров блоков.

**Шаги воспроизведения:**

1. Открыть Playground для `richelieu`.
2. Последовательно выбрать варианты 1, 3, 4, 5, 8.
3. Запустить шифрование или расшифрование.

**Фактический результат:**
Возникают ошибки:

* variant 1: `richelieu: text length (12) must equal sum of block sizes (11)`
* variant 3: `richelieu: text length (19) must equal sum of block sizes (16)`
* variant 4: `richelieu: text length (18) must equal sum of block sizes (16)`
* variant 5: `richelieu: text length (19) must equal sum of block sizes (16)`
* variant 8: `richelieu: text length (33) must equal sum of block sizes (32)`

**Ожидаемый результат:**
Методические варианты должны выполняться без ошибок формата данных.

**Подтверждённая причина:**
Проблема была в `data/richelieu/variants.json`: в вариантах 1, 3, 4, 5 и 8 текст был занесён с лишними символами / пробелами относительно блоков ключа. По локальной PDF-методичке длины должны совпадать.

**Исправление:**
Исправлены тексты вариантов 1, 3, 4, 5 и 8 в `data/richelieu/variants.json` так, чтобы их длина совпадала с суммой размеров блоков и сценарии из методички выполнялись без ошибок.

**Предполагаемый слой проблемы:** `data`

### UI-PZ4-PZ5-002

**Шифр:** `morse`
**Область:** Variants / data quality
**Серьёзность:** low
**Статус:** fixed

**Симптомы:** все варианты выполняются, но в расшифрованном тексте встречаются орфографические ошибки.

**Шаги воспроизведения:**

1. Открыть Playground для `morse`.
2. Проверить все доступные варианты.
3. Сравнить расшифрованный текст с ожидаемым содержимым варианта.

Исправлены тексты вариантов по подтверждаемым фразам из методички, затем заново сохранены корректные шифротексты Морзе для этих вариантов.

### UI-PZ4-PZ5-003

**Шифр:** `vernam`
**Область:** Free text / UX / data quality
**Серьёзность:** low
**Статус:** fixed

**Симптомы:** свободный текст работает, но ключ по умолчанию подобран неудачно.

**Шаги воспроизведения:**

1. Открыть Playground для `vernam`.
2. Использовать режим свободного текста с предзаполненным ключом.
3. Попробовать шифрование и расшифрование.
4. Затем ввести произвольный собственный ключ и повторить.

**Фактический результат:**

**Ожидаемый результат:**
Значение по умолчанию должно быть пригодным для демонстрации корректной работы шифра.

**Исправление:**
`meta.raw_key_example` заменён на рабочий и наглядный пример `{"keyword": "ШИФР", "apply_to": "all"}` без изменения контракта `parse_key()`.

**Предполагаемый слой проблемы:** `data` / `ux`

### UI-PZ4-PZ5-004

**Шифр:** `adfgvx`
**Область:** Variants / methodics consistency
**Серьёзность:** medium
**Статус:** unresolved

**Симптомы:** все варианты проходят без технических ошибок, но результат выглядит как невразумительный набор символов.

**Шаги воспроизведения:**

1. Открыть Playground для `adfgvx`.
2. Проверить свободный текст и все доступные варианты.
3. Сравнить результат с ожидаемой интерпретацией по методичке.

**Фактический результат:**
Шифрование и расшифрование выполняются, но содержательная корректность результата вызывает сомнение.

**Ожидаемый результат:**
Результат должен быть понятен и соответствовать методическим ожиданиям.

**Подтверждённая причина:**
Проблема была не в `variants.json`, а в реализации `src/miskzi_ciphers/ciphers/adfgvx/cipher.py`: фиксированная таблица замен не совпадала с таблицей 24 из ПЗ-04. Из-за этого методический пример `UNIVERSITY` / `DRIVE` не воспроизводился.

**Исправление:**
Таблица `GRID_ROWS` приведена к подтверждаемому виду из методички. После исправления пример из ПЗ-04 даёт `GFAFFAFDFGVXFDFGGDGG`, а обратное преобразование возвращает `UNIVERSITY`.

**Предполагаемый слой проблемы:** `methodics` / `data` / `unknown`

### UI-PZ4-PZ5-009

**Шифр:** `rubik_2x2`
**Область:** Variants / completeness
**Серьёзность:** medium
**Статус:** partial

**Симптомы:** варианты занесены частично и, по наблюдению, некорректно.

**Шаги воспроизведения:**

1. Открыть Playground для `rubik_2x2`.
2. Проверить наличие и работоспособность вариантов.
3. Сравнить набор с методичкой.

**Фактический результат:**
Варианты частично отсутствуют и текущие доступные записи не проходят.

**Ожидаемый результат:**
Набор вариантов должен быть полным и корректным.

**Подтверждённая часть проблемы:**
По локальной PDF-методичке для ПЗ-05 действительно ожидается более полный набор вариантов, чем текущие 3 записи в `data/rubik_2x2/variants.json`.

**Что удалось установить:**
Текущие 3 варианта в репозитории теперь работоспособны и их ключи парсятся корректно. Однако надёжно восстановить недостающие варианты только по данным и без более глубокого пересмотра реализации `rubik_2x2` не удалось: результаты текущего алгоритма недостаточно уверенно совпадают с методическими ожиданиями для дополнительных сценариев.

**Остаточная неопределённость:**
Дефект полноты вариантов остаётся частично открытым. В этой итерации неподтверждённые варианты не добавлялись.

**Предполагаемый слой проблемы:** `data` / `methodics`
