# Формализация алгоритмов для ПР9 и ПР10

Назначение документа:
- зафиксировать состояние формализации алгоритмов до реализации в коде;
- отделить подтвержденные требования от неполных или неуточненных;
- использовать документ как техническую опору для дальнейшей реализации `practice-layer`.

Ограничение документа:
- если точных данных недостаточно, это указывается явно;
- неподтвержденные места не должны считаться утвержденной спецификацией.

Дополнительное правило:

- рабочее проектное решение может быть принято даже при неполной обратной совместимости со старым `.exe`, если это явно зафиксировано как учебно-совместимая политика проекта.

## Политика интерпретации результатов

- целью реализации является учебно-совместимое поведение алгоритмов, а не побайтное совпадение со сторонними `.exe`;
- корректность результата определяется:
  - правильностью алгоритма;
  - согласованностью выбранных правил: алфавит, нормализация, filler;
  - воспроизводимостью trace;
- допускаются отличия от старых `.exe`, если:
  - они объяснимы;
  - они отражены в документации;
  - они не противоречат базовой логике алгоритма;
- при расхождениях приоритет имеет:
  1. формализованная логика алгоритма;
  2. прозрачность trace;
  3. воспроизводимость результата;
- проект не ставит цель полной обратной совместимости со старыми программами.

## 1. Playfair

### Подтвержденные факты

- алгоритм относится к биграммным шифрам;
- используется одна матрица;
- текст разбивается на биграммы;
- для каждой биграммы применяется одно из правил:
  - одна строка;
  - один столбец;
  - прямоугольник;
- требуется обработка повторяющихся букв;
- требуется обработка нечётной длины текста.

Источник:
- `docs/external-materials/ПР_10.docx`

### Алфавит

Рабочее проектное решение:

- поддержать выбор алфавита `RU` / `EN`;
- для `EN` использовать латинский алфавит `A-Z`;
- для `RU` использовать отдельный русский режим;
- символы вне выбранного алфавита по умолчанию исключать из нормализованного текста, но обязательно отображать это в trace.

Ограничение:

- это рабочее проектное решение;
- полное совпадение со старым `.exe` не гарантируется.

### Матрица

Подтвержденные данные:
- матрица обязательна;
- матрица является частью учебного сценария ПР10.

Рабочее проектное решение:

- матрицу строить по ключу с удалением дублей;
- символы алфавита, отсутствующие в ключе, дополняют матрицу после ключа;
- построение матрицы выполняется в `practice-layer` или в общем биграммном helper.

Ограничение:

- точный формат русской матрицы требует дополнительной фиксации в реализации;
- это решение задает учебную политику проекта, а не бинарную совместимость со старым `.exe`.

### Правила

Подтвержденные данные:
- для пары в одной строке применяется отдельное правило;
- для пары в одном столбце применяется отдельное правило;
- для пары, образующей прямоугольник, применяется правило прямоугольника.

Рабочее проектное решение:

- реализовать стандартный учебный `Playfair`;
- для `encrypt` использовать стандартные правила строки, столбца и прямоугольника;
- для `decrypt` использовать обратные стандартные правила.

Ограничение:

- это рабочее проектное решение;
- полное совпадение со старой программой не гарантируется.

### Filler

Подтвержденные данные:
- filler требуется для обработки нечётной длины текста;
- filler требуется для разрыва повторяющихся букв в биграмме.

Рабочее проектное решение:

- использовать filler:
  - `X` для `EN`;
  - `Х` для `RU`;
- одиночную букву дополнять filler;
- нечётную длину текста дополнять filler.

### Повтор букв

Подтвержденные данные:
- повторяющиеся буквы должны обрабатываться отдельно до применения алгоритма к биграмме.

Рабочее проектное решение:

- повтор в биграмме разрывать filler;
- результат разрыва должен явно отражаться в trace.

## 2. Wheatstone

### Подтвержденные факты

- алгоритм относится к биграммным шифрам;
- используются две матрицы;
- текст разбивается на биграммы;
- требуется анализ каждой биграммы.

Источник:
- `docs/external-materials/ПР_10.docx`

### Вариант алгоритма

Подтвержденные данные:
- в методичке указан шифр Уитстона;
- для варианта 5 задан ciphertext `Rk*t0nfn:kтх_G;pъЖ`.

Рабочее проектное решение:

- принять учебный вариант `Wheatstone` как `two-square` / `double Playfair`-подобный шифр с двумя матрицами;
- считать это реализацией учебного варианта по требованиям ПР10, а не гарантированной копией старого `.exe`.

### Матрицы

Подтвержденные данные:
- используются две матрицы;
- обе матрицы должны отображаться в учебном режиме.

Рабочее проектное решение:

- обе матрицы строить в `practice-layer` или в общем биграммном helper;
- обе матрицы должны быть доступны trace-слою как часть учебного результата.

### Правила

Подтвержденные данные:
- правила Уитстона отличаются от правил Плейфера;
- результат должен объясняться по каждой биграмме.

Рабочее проектное решение:

- обработка биграмм должна давать trace по каждой паре;
- одиночную букву дополнять filler;
- смешанные или неалфавитные символы отображать как исключенные или необработанные в trace.

Ограничение:

- точное совпадение с историческим `.exe` не гарантируется;
- это учебно-совместимая политика проекта.

## 3. Caesar (ПР9)

### Подтвержденные факты

- для варианта 5 задано:
  - `N = 5`
  - `k1 = (N * 2 + 13) mod 17`
  - `k2 = (N * 4 - 6) mod 13`
- вычисленные значения:
  - `k1 = 6`
  - `k2 = 1`

Источник:
- требования ПР9, зафиксированные в `docs/practice/practice-09-requirements.md`

### Алфавит

Подтвержденные данные:
- в текущем проекте `caesar` реализован в `src/miskzi_ciphers/ciphers/caesar/cipher.py`;
- текущая реализация использует русский алфавит.

Рабочее проектное решение:

- использовать алфавит из методички ПР9;
- для варианта 5 зафиксировать `k1 = 6`, `k2 = 1`;
- текущий `caesar` можно использовать как вычислительное ядро, если алфавит совпадает или если `practice-layer` явно задает нужный алфавит.

## 4. Invert 255

### Подтвержденные факты

- в ПР9 требуется режим “инверсия по дополнению до 255”.

Источник:
- требования ПР9, зафиксированные в `docs/practice/practice-09-requirements.md`

### Кодировка

Рабочее проектное решение:

- реализовать `Invert 255` как `byte-level` преобразование над `Windows-1251`.
- MVP-2 реализует это решение в `practice-layer` как изолированный учебный режим ПР9.

Ограничение:

- это учебно-совместимая политика проекта;
- полная обратная совместимость со старым `.exe` не гарантируется.

### Правило

Подтвержденные данные:
- название алгоритма указывает на преобразование по схеме дополнения до `255`.

Рабочее проектное решение:

- для каждого байта `x` вычислять `y = 255 - x`;
- результат интерпретировать обратно в текст в рамках той же кодировки `Windows-1251`.
- если результирующий байт не декодируется или дает проблемный символ, это должно отражаться в trace/notes без аварийного завершения сценария.

## 5. Перестановка

### Подтвержденные факты

- в ПР9 требуется алгоритм перестановки символов.

Рабочее проектное решение:

- не пытаться угадывать поведение старого `.exe`;
- принять минимальный учебный режим простой перестановки с явно описанным правилом;
- использовать перестановку соседних символов по парам;
- для нечётной длины последний символ сохранять без изменения;
- правило перестановки должно быть явно показано в trace и в отчете.
- MVP-2 реализует этот режим как `pair_swap` внутри `practice-layer`;
- полная совместимость с режимом перестановки старого `.exe` не заявляется.

## 6. Политики

### Обработка символов вне алфавита

Рабочее проектное решение:

- для ПР10 символы вне выбранного алфавита по умолчанию исключать из нормализованного текста;
- исключенные символы обязательно отражать в trace;
- для ПР9 политика должна задаваться явно алгоритмом или practice-сценарием.

### Регистр

Рабочее проектное решение:

- в `practice-layer` использовать явную нормализацию регистра перед вычислением;
- сведения об исходном регистре, если они важны для отчета, отражать в trace;
- политика восстановления регистра не считается обязательной для первого этапа.

### Пробелы

Рабочее проектное решение:

- для ПР10 пробелы исключать на этапе нормализации перед разбиением на биграммы;
- для ПР9 участие пробелов определяется конкретным учебным режимом;
- для гистограмм ПР9 строить частоты по символам текста и показывать абсолютные и относительные частоты.

## 7. Дополнительные проектные решения для ПР9

### Vigenere

Рабочее проектное решение:

- для ручной задачи варианта 5 использовать латинский алфавит `A-Z`;
- использовать ciphertext `yoikyoj` и key `work`;
- если текущий `vigenere` работает только по `RU_33`, для ПР9 нужен отдельный `practice-trace` или расширение параметров без ломки основного контракта.

### Gronsfeld

Рабочее проектное решение:

- ключ `7 5 13 19` трактовать как последовательность чисел `[7, 5, 13, 19]`, а не как отдельные цифры;
- если текущий `gronsfeld` парсит только цифры, для ПР9 нужен отдельный `practice-trace` и отдельный parser.

### Гистограммы

Рабочее проектное решение:

- строить гистограммы по символам текста;
- показывать абсолютные и относительные частоты;
- использовать их для сравнения исходного и зашифрованного текста.

## 8. Дополнительные проектные решения для ПР10

### Одиночная буква

Рабочее проектное решение:

- одиночную букву дополнять filler;
- факт дополнения обязательно показывать в trace.

### Смешанные символы в ciphertext варианта 5

Рабочее проектное решение:

- считать смешанные символы риском старой методички или старой программы;
- до полной обратной совместимости обрабатывать текст через выбранный алфавитный режим;
- исключенные или необработанные символы явно показывать в trace.

## Итоговый статус

Подтверждено:
- для ПР10 подтверждены общие требования к Плейферу и Уитстону как к биграммным шифрам с матрицами и анализом пар;
- для ПР9 подтверждены формулы `k1` и `k2` для Caesar варианта 5;
- для ПР9 подтверждено наличие режима `Invert 255` и режима перестановки как отдельных требований;
- для части алгоритмов приняты рабочие проектные решения без гарантии полного совпадения со старым `.exe`.
- MVP-2 ПР9 реализует `Invert 255` как учебно-совместимое byte-level преобразование над `Windows-1251`;
- MVP-2 ПР9 реализует `pair_swap` как учебную простую перестановку соседних символов.

Не формализовано полностью:
- точный исторический вариант `Wheatstone` из старого `.exe`;
- полная обратная совместимость `Invert 255` со старой программой;
- полная обратная совместимость режима перестановки со старой программой;
- окончательная спецификация русского алфавита для `Playfair`;
- единые политики текста для всех учебных режимов без параметризации.
