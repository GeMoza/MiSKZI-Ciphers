# Практическая работа №10 – требования к поддержке в MiSKZI-Ciphers

## 1. Назначение документа

Этот документ фиксирует требования к поддержке практической работы №10 внутри проекта `MiSKZI-Ciphers`.

Документ не описывает реализацию и не фиксирует уже выполненную доработку.

Документ используется как техническое задание для последующей реализации.

## 2. Источник требований

Подтвержденные факты:
- требования к ПР10 основаны на материале `docs/external-materials/ПР_10.docx`;
- сторонние `.exe` не должны использоваться в рамках проекта;
- режим ПР10 должен реализовываться средствами собственной программы `MiSKZI-Ciphers`.

Ограничения источника:
- файл `docs/external-materials/ПР_10.docx` находится в каталоге `docs/external-materials/`;
- материалы из `docs/external-materials/` имеют статус `non-authoritative`;
- до дополнительной формализации точная спецификация старых `.exe` должна считаться внешним требованием, а не частью текущего контракта проекта.

## 3. Суть практической работы

Подтвержденные факты:
- ПР10 посвящена биграммным шифрам;
- в ПР10 рассматриваются шифр Уитстона и шифр Плейфера;
- работа требует использования матриц шифрования;
- работа требует обязательного анализа каждой пары символов;
- ПР10 представляет собой учебный сценарий, а не только вызов `encrypt/decrypt`.

Предположения:
- режим ПР10 должен совмещать выполнение алгоритма, отображение матриц и подготовку данных для отчета;
- режим ПР10 должен быть отдельным учебным сценарием поверх базового слоя шифров.

## 4. Требуемые функции программы

Подтвержденные факты:
- ввод текста;
- ввод ключа;
- шифрование;
- вывод результата;
- отображение матриц;
- работа с биграммами;
- пошаговый разбор;
- работа с `.txt` как дополнительная возможность.

Факты о текущем проекте:
- в `src/miskzi_ciphers/ui/app.py` уже есть текстовые поля и базовый вызов шифров;
- в `src/miskzi_ciphers/cli.py` уже есть чтение текста из файла через `--text-file` и запись результата через `--out`;
- в текущем UI нет специализированного режима отображения матриц и анализа биграмм;
- в текущем проекте нет готового публичного trace-слоя для учебного сценария ПР10.

## 5. Алгоритмы ПР10

### 5.1 Плейфер

Подтвержденные факты:
- используется матрица;
- используются биграммы;
- применяются правила:
  - одна строка;
  - один столбец;
  - прямоугольник;
- требуется обработка:
  - повторяющихся букв;
  - нечётной длины текста.

Факты о текущем проекте:
- шифр Плейфера отсутствует в `src/miskzi_ciphers/ciphers/`;
- для Плейфера требуется новая реализация;
- для Плейфера требуется общая биграммная инфраструктура.

Предположения:
- правила нормализации текста, filler и алфавит должны быть формализованы отдельно до реализации;
- логика построения матрицы должна быть отделена от учебного trace.

### 5.2 Уитстон

Подтвержденные факты:
- используются две матрицы;
- используются биграммы;
- правила преобразования отличаются от Плейфера;
- требуется анализ каждой биграммы.

Факты о текущем проекте:
- шифр Уитстона отсутствует в `src/miskzi_ciphers/ciphers/`;
- для Уитстона требуется новая реализация;
- для Уитстона требуется общая биграммная инфраструктура.

Предположения:
- точная спецификация правил Уитстона должна быть формализована отдельно до реализации;
- матрицы и правила анализа не должны встраиваться в базовый контракт шифра.

Документ не содержит решения для варианта 5.

## 7. Требования к учебному режиму ПР10

Подтвержденные факты:
- режим ПР10 должен позволять выполнять учебный сценарий без запуска сторонних `.exe`;
- режим ПР10 должен поддерживать не только итоговый результат, но и анализ промежуточных преобразований.

Минимальный UI:
- выбор алгоритма (`Wheatstone` / `Playfair`);
- режим `encrypt` / `decrypt`;
- поле текста;
- поле ключа;
- отображение матрицы или матриц;
- список биграмм;
- таблица преобразований;
- выделение `3`-й, `7`-й, `10`-й биграмм;
- вывод результата;
- экспорт.

Предположения:
- режим ПР10 должен быть отдельным учебным сценарием, а не расширением обычного списка шифров;
- UI ПР10 должен вызывать обычные шифры и дополнительные `practice`-сервисы, не изменяя основной `CipherProtocol`.

## 8. Trace / промежуточные расчеты

Обязательные данные для каждой биграммы:
- исходная пара;
- координаты в матрице;
- правило (`строка` / `столбец` / `прямоугольник`);
- результат;
- комментарий.

Обязательные данные для Плейфера:
- финальная матрица.

Обязательные данные для Уитстона:
- обе матрицы.

Факты о текущем проекте:
- текущий публичный контракт шифров не возвращает trace-объекты;
- trace для ПР10 должен быть отдельным учебным слоем.

## 8.1 Архитектурная граница учебного режима

Обязательное:
- не менять `CipherProtocol`;
- не добавлять trace в `cipher.py`;
- матрицы не являются частью контракта шифра;
- биграммная логика не является частью базового API;
- учебный режим должен быть отдельным слоем.
- построение матриц должно выполняться вне `cipher.py`;
- построение матриц должно выполняться в общем биграммном helper или в `practice-layer`;
- `cipher` не должен самостоятельно строить матрицу, если это не требуется для базового `encrypt/decrypt`;
- матрица является частью учебного сценария, а не обязательного API шифра.

### Взаимодействие practice-layer и core

- шифры используются как вычислительное ядро;
- `practice-layer` управляет:
  - нормализацией;
  - биграммами;
  - матрицами;
  - trace;
- UI работает через `practice`-сервис;
- запрещено вызывать `cipher` напрямую из UI ПР10.

Предположения:
- учебный режим ПР10 может использовать предлагаемую структуру вида `src/miskzi_ciphers/practice/practice_10/`;
- конкретные имена модулей могут отличаться, но `practice-layer` должен оставаться изолированным от базового слоя шифров.

## 9. Общая биграммная инфраструктура

Обязательное требование:

должен быть добавлен общий helper для:
- нормализации текста;
- разбиения на биграммы;
- вставки filler;
- обработки повторов;
- построения матриц.

Архитектурные требования:
- этот модуль должен быть переиспользуем для Плейфера и Уитстона;
- этот модуль не должен быть привязан к конкретному шифру;
- этот модуль не должен менять базовый контракт шифров.

## 9.1 Pipeline обработки текста

Обязательная последовательность обработки:
- входной текст;
- нормализация текста;
- обработка регистра;
- удаление или сохранение символов вне алфавита;
- разбиение на биграммы;
- обработка повторов;
- вставка filler;
- применение алгоритма;
- сборка результата.

Архитектурные требования:
- pipeline должен быть единым для Плейфера и Уитстона;
- различия допустимы только на этапе применения алгоритма.

## 10. Нерешенные вопросы

Открытые вопросы:
- точная спецификация Уитстона;
- алфавит (`RU` / `EN` / смешанный);
- правила для символов вне алфавита;
- filler;
- регистр;
- поведение для одной буквы;
- как интерпретировать символы типа `*`, `_`, `:`.
- где именно должен строиться ключевой квадрат (`helper` или `cipher`);
- должен ли pipeline быть полностью общим или допускаются частные реализации.

Дополнительные вопросы для формализации:
- нужно ли сохранять символы вне алфавита как есть или включать их в матрицы;
- как именно нормализовать `Ё` и смешанный текст;
- должны ли демонстрационные слова и ручная задача использовать один и тот же режим нормализации;
- должен ли экспорт включать только итоговую таблицу или полный trace по всем биграммам.

## 11. Предлагаемый план реализации

1. формализовать правила Плейфера и Уитстона;
2. создать `bigram` helper;
3. реализовать оба шифра;
4. создать `practice-layer`;
5. реализовать trace;
6. добавить UI-вкладку ПР10;
7. добавить тесты;
8. добавить экспорт.

## 12. Ограничения

Обязательные ограничения:
- не запускать `.exe`;
- не менять контракт шифров;
- не добавлять trace в `cipher`;
- не смешивать с обычными шифрами;
- изолировать в `practice`.

Архитектурные следствия:
- учебный режим ПР10 не должен изменять семантику базовых `encrypt()/decrypt()`;
- матрицы, анализ биграмм и учебные проверки должны жить вне обычного списка шифров;
- все предположения по ПР10 должны быть явно зафиксированы до реализации.
